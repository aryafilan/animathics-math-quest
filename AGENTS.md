# Math Quest — development rules

- Preserve the original reference HTMLs. Keep all game source files. The main catalog shows the user's 10 selected games in the specified order; all other games remain playable in the collapsed archive. Preserve the selection unless explicitly instructed. Metadata `archived` controls the split. Do not delete any game.
- New worlds must differ in actual gameplay, not only palette, questions, or tile targets.
- Each world must have original mathematical actions, visual identity, multiple missions, keyboard/touch controls as relevant, and a return-to-catalog link.
- Math tests are mandatory; report browser testing honestly. Do not label untested prototypes polished releases.
- Add metadata to arcade/catalog.json and the root index.html. Keep worlds/catalog.json and legacy games.json for existing validation.

- Prefer direct playable actions, replayable challenges, responsive controls and feedback; do not present a prototype as a polished release before visual and end-to-end testing.
